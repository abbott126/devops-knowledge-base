Configuration 配置

ConfigMaps配置信息

ConfigMap 是一个 API 对象，用于以键值对的形式存储非机密数据。 Pod 可以使用 ConfigMap 作为 环境变量、命令行参数或配置文件;

Pod 引用 ConfigMap

您可以编写一个 Pod spec ，该规范引用一个 ConfigMap，并根据 ConfigMap 中的数据配置该 Pod 中的容器。Pod 和 ConfigMap 必须位于同一个命名空间中。

创建configmap文件ex-configmap.yaml

apiVersion: v1
kind: ConfigMap
metadata:
  name: myconfigmap
data:
  username: k8s-admin
  access_level: "1"

创建configmap

[root@master configmap]# kubectl  apply -f    configmap.yaml
configmap/myconfigmap created

# 使用别名
[root@master configmap]# ka  -f  configmap.yaml
configmap/myconfigmap unchanged

查看configmap

[root@master configmap]# kubectl  get  configmap
NAME               DATA   AGE
kube-root-ca.crt   1      9d
myconfigmap        2      114s

创建pod引用 myconfigmap

  • 创建Pod文件configmap-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: env-configmap
spec:
  containers:
    - name: app
      command: ["/bin/sh", "-c", "printenv"]
      image: https://docker.aityp.com/#google_vignette/busybox:latest
      envFrom:
        - configMapRef:
            name: myconfigmap
  • 创建Pod 
[root@master configmap]# ka   -f configmap-pod.yaml
  • 查看日志

Example:

需求： 根据不同环境发布pod

dev prod

以下是为 开发环境（dev） 和 生产环境（prod） 分别创建 Nginx Pod 及对应的 ConfigMap 的完整配置，实现不同环境下 Nginx 配置的隔离与切换。

场景说明

  • 开发环境（dev）：Nginx 监听 8080 端口，显示开发环境标识页面。
  • 生产环境（prod）：Nginx 监听 80 端口（标准端口），显示生产环境标识页面，且配置更严格（如关闭目录浏览）。

步骤 1：创建命名空间（隔离环境）

先为两个环境创建独立的命名空间（避免资源冲突）：

# 创建开发环境命名空间
kubectl create namespace dev

# 创建生产环境命名空间
kubectl create namespace prod

步骤 2：创建环境专属的 ConfigMap

为 dev 和 prod 环境分别定义 ConfigMap，存储各自的 Nginx 配置文件和首页内容。

2.1 开发环境 ConfigMap（dev 命名空间）

# configmap-nginx-dev.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-config  # 同名 ConfigMap，通过命名空间隔离
  namespace: dev      # 开发环境命名空间
data:
  # Nginx 配置文件（键为文件名，值为配置内容）
  default.conf: |
    server {
      listen 8080;  # 开发环境用 8080 端口
      server_name localhost;
      root /usr/share/nginx/html;
      index index.html;

      # 开发环境允许目录浏览（方便调试）
      autoindex on;
    }

  # 首页内容（区分环境标识）
  index.html: |
    <html>
      <head><title>Dev Environment</title></head>
      <body><h1>Welcome to Development Environment (dev)</h1></body>
    </html>

创建开发环境 ConfigMap：

kubectl apply -f configmap-nginx-dev.yaml

2.2 生产环境 ConfigMap（prod 命名空间）

# configmap-nginx-prod.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-config  # 与 dev 环境同名，通过命名空间隔离
  namespace: prod     # 生产环境命名空间
data:
  # Nginx 配置文件（生产环境更严格）
  default.conf: |
    server {
      listen 80;  # 生产环境用标准 80 端口
      server_name localhost;
      root /usr/share/nginx/html;
      index index.html;

      # 生产环境关闭目录浏览，增强安全性
      autoindex off;

      # 生产环境添加缓存头（优化性能）
      location ~* \.(html|css|js)$ {
        expires 1h;
        add_header Cache-Control "public";
      }
    }

  # 首页内容（生产环境标识）
  index.html: |
    <html>
      <head><title>Production Environment</title></head>
      <body><h1>Welcome to Production Environment (prod)</h1></body>
    </html>

创建生产环境 ConfigMap：

kubectl apply -f configmap-nginx-prod.yaml

步骤 3：创建环境专属的 Nginx Pod

Pod 分别部署在 dev 和 prod 命名空间，引用对应环境的 ConfigMap。

3.1 开发环境 Nginx Pod（dev 命名空间）

# pod-nginx-dev.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-dev
  namespace: dev  # 开发环境命名空间
spec:
  containers:
  - name: nginx
    image: nginx:latest
    ports:
    - containerPort: 8080  # 对应 dev 环境 ConfigMap 中的端口
    volumeMounts:
    - name: nginx-config-volume  # 挂载 ConfigMap 中的配置文件
      mountPath: /etc/nginx/conf.d  # Nginx 配置目录
    - name: nginx-html-volume     # 挂载 ConfigMap 中的首页
      mountPath: /usr/share/nginx/html  # Nginx 静态文件目录
  volumes:
  - name: nginx-config-volume
    configMap:
      name: nginx-config  # 引用 dev 环境的 ConfigMap
      items:
      - key: default.conf  # ConfigMap 中的配置文件名
        path: default.conf  # 挂载到容器内的文件名
  - name: nginx-html-volume
    configMap:
      name: nginx-config  # 引用 dev 环境的 ConfigMap
      items:
      - key: index.html    # ConfigMap 中的首页文件名
        path: index.html   # 挂载到容器内的文件名

创建开发环境 Pod：

kubectl apply -f pod-nginx-dev.yaml

3.2 生产环境 Nginx Pod（prod 命名空间）

# pod-nginx-prod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-prod
  namespace: prod  # 生产环境命名空间
spec:
  containers:
  - name: nginx
    image: nginx:latest
    ports:
    - containerPort: 80  # 对应 prod 环境 ConfigMap 中的端口
    volumeMounts:
    - name: nginx-config-volume  # 挂载 ConfigMap 中的配置文件
      mountPath: /etc/nginx/conf.d
    - name: nginx-html-volume     # 挂载 ConfigMap 中的首页
      mountPath: /usr/share/nginx/html
  volumes:
  - name: nginx-config-volume
    configMap:
      name: nginx-config  # 引用 prod 环境的 ConfigMap
      items:
      - key: default.conf
        path: default.conf
  - name: nginx-html-volume
    configMap:
      name: nginx-config  # 引用 prod 环境的 ConfigMap
      items:
      - key: index.html
        path: index.html

创建生产环境 Pod：

kubectl apply -f pod-nginx-prod.yaml

验证环境隔离与配置生效

1. 查看资源部署状态

# 查看 dev 环境资源
kubectl get cm,pod -n dev

# 查看 prod 环境资源
kubectl get cm,pod -n prod

确保 ConfigMap 和 Pod 状态均为 Running 或 Active。

2. 验证开发环境配置

# 进入 dev 环境 Pod
kubectl exec -it nginx-dev -n dev -- bash

# 验证 Nginx 配置（监听 8080 端口，允许目录浏览）
cat /etc/nginx/conf.d/default.conf

# 验证首页内容（开发环境标识）
cat /usr/share/nginx/html/index.html

# 启动 Nginx（容器默认已启动，可测试端口）
curl localhost:8080  # 应返回开发环境首页
exit

3. 验证生产环境配置

# 进入 prod 环境 Pod
kubectl exec -it nginx-prod -n prod -- bash

# 验证 Nginx 配置（监听 80 端口，关闭目录浏览）
cat /etc/nginx/conf.d/default.conf

# 验证首页内容（生产环境标识）
cat /usr/share/nginx/html/index.html

# 测试端口
curl localhost:80  # 应返回生产环境首页
exit

核心优势

  1. 环境隔离：通过命名空间（dev/prod）和同名 ConfigMap 实现环境隔离，切换环境时无需修改 Pod 配置，只需切换命名空间。
  2. 配置与镜像解耦：Nginx 镜像不变，通过 ConfigMap 动态注入不同环境的配置（端口、首页、安全策略等），避免为不同环境构建多个镜像。
  3. 灵活更新：若需修改某环境配置，只需更新对应命名空间的 ConfigMap，文件挂载方式会自动同步（约 10 秒生效），无需重启 Pod。

扩展：通过 Service 暴露服务（可选）

若需外部访问，可为两个环境的 Pod 创建 Service：

# service-nginx-dev.yaml（dev 环境，暴露 8080 端口）
apiVersion: v1
kind: Service
metadata:
  name: nginx-dev-svc
  namespace: dev
spec:
  selector:
    app: nginx-dev  # 需在 Pod 的 metadata.labels 中添加 app: nginx-dev
  ports:
  - port: 8080
    targetPort: 8080
  type: NodePort  # 或 LoadBalancer（云环境）

同理为 prod 环境创建 Service，暴露 80 端口即可。

通过这种方式，可高效管理多环境的 Nginx 配置，实现 “一次镜像，多环境复用” 的目标。

etcd数据库使用

操作类型 命令示例 说明
写入数据 etcdctl put /app/name "my-service" 新增或覆盖键 /app/name 的值为 my-service
读取数据 etcdctl get /app/name 读取单个键的值；加 -prefix 可读取前缀匹配的所有键（如 /app/ 下的所有键）
删除数据 etcdctl del /app/name 删除单个键；加 -prefix 可删除前缀匹配的所有键
监听数据 etcdctl watch /app/name 实时监听键的变化（新增、修改、删除），加 -prefix 可监听前缀匹配的键
