json 语言：

JSON（JavaScript Object Notation）是一种轻量级的数据交换格式，基于 ECMAScript 规范的子集，采用文本格式来存储和表示数据，具有简洁、易读、跨平台等特点。

核心特性

  • 简洁性：语法简单，采用键值对（key-value）结构，使用大括号{}表示对象，中括号[]表示数组，数据之间用逗号,分隔，无冗余标签，相比 XML 更紧凑。

  • 可读性：结构清晰，人类可直接阅读和编辑，例如：

{
  "name": "Alice",
  "age": 25,
  "isStudent": false,
  "hobbies": ["reading", "coding"],
  "address": {
    "city": "Beijing",
    "street": "Main Road"
  }
}

  • 跨语言支持：几乎所有主流编程语言（如 Python、Java、JavaScript、C# 等）都内置或有第三方库支持 JSON 的解析和生成，是不同系统间数据交换的理想选择。

  • 数据类型有限但实用：支持字符串（需用双引号包裹）、数字（整数、浮点数）、布尔值（true/false）、null、对象（键值对集合）、数组（有序值列表）。

应用场景

  • 前后端数据交互：网页前端（如 JavaScript）与后端服务器之间通常用 JSON 传递数据，是 AJAX 请求的主要数据格式。
  • 配置文件：部分软件或框架使用 JSON 作为配置文件格式（如 npm 的package.json）。
  • API 接口：大量 RESTful API 以 JSON 格式返回数据，方便客户端解析处理。
  • 数据存储：小型应用中可直接用 JSON 文件存储简单数据，替代轻量级数据库。

语法规则

  • 键必须用双引号""包裹（区别于 JavaScript 对象的键可省略引号）。
  • 字符串必须用双引号""包裹，不能用单引号。
  • 末尾不能有多余的逗号（如数组或对象最后一个元素后不能加逗号）。
  • 不支持注释（这是与 YAML 的主要区别之一）。

模版 template

Ansible使用Jinja2模板来启用动态表达式并访问变量和事实。您可以将模板与模板一起使用。例如，您可以为配置文件创建一个模板，然后将该配置文件部署到多个环境中，并为每个环境提供正确的数据（IP地址、主机名、版本）

比如： 我们可以使用jinja2定义模版，模版可以获取主机信息，匹配到我们的配置文件；

Jinja2 语法：

Jinja是一种快速、富有表现力、可扩展的模板引擎。模板中的特殊占位符允许编写类似于Python语法的代码。然后将数据传递给模板以呈现最终文档。

它包括：

  • 模板继承和包含。
  • 在模板中定义和导入宏。
  • HTML模板可以使用自动脱码来防止XSS被不可信的用户输入。
  • 沙盒环境可以安全地渲染不受信任的模板。
  • 非同步支持生成模板，无需额外的语法即可自动处理同步和非同步功能。
  • 与Babel的I18N支持。
  • 模板被及时编译为优化的Python代码并缓存，也可以提前编译。
  • 异常指向模板中的正确行，以使调试更容易。
  • 可扩展的过滤器、测试、函数，甚至语法。

Jinja的理念是，如果可能的话，应用程序逻辑属于Python，但它不应该因过多限制功能而使模板设计师的工作变得困难。

条件语句when ：

最简单的条件语句适用于单个任务。创建任务，然后添加应用测试的 when 语句。when 子句是一个原始的 Jinja2 表达式，没有双大括号（参见引用简单变量 ）。运行任务或 playbook 时，Ansible 会评估所有主机的测试。在测试通过的任何主机上（返回值 True），Ansible 都会运行该任务。

Example:

[root@ansible-server playbook]# cat when/ex1.yaml 
---
- hosts: all
  tasks: 
  - name: modify hostname
    hostname:
      name: web1-server.com
    when: ansible_default_ipv4['address'] == "192.168.1.103"  
  - name: modify hostname
    hostname:
      name: web2-server.com
    when: ansible_default_ipv4['address'] == "192.168.1.105"  
  - name: modify hostname
    hostname:
      name: db1-server.com
    when: ansible_default_ipv4['address'] == "192.168.1.102"
  - name: modify hostname
    hostname:
      name: db2-server.com
    when: ansible_default_ipv4['address'] == "192.168.1.106"  
  - name: install  httpd
    apt:
      name: apache2
      state:  installed
    when: ansible_facts['os_family'] == "Debian"

Handlers: running operations on change

修改配置文件之后再触发动作

Notify 任务执行了；Notify 出发一个动作 Handlers

Example:

- hosts: all
  vars: 
    - http_path: /etc/httpd/conf
    - page_pash: /var/www/html
    - local_path: /etc/httpd

  tasks:
  - name: install httpd
    yum:
      name: httpd
      state: installed
    when: ansible_facts['os_family'] == "RedHat"
  - name: 修改配置文件
    template:
      src: httpd.j2
      dest: '{{ http_path }}/httpd.conf'
    notify:
      - restart httpd
    when: ansible_facts['os_family'] == "RedHat"
  - name: 启动服务
    service:
      name: httpd
      state: started
    when: ansible_facts['os_family'] == "RedHat"
  - name: update html page
    template:
      src: index.j2
      dest: '{{ page_pash }}/index.html'
  handlers:
    - name: restart httpd
      service:
        name: httpd
        state: restarted
      when: ansible_facts['os_family'] == "RedHat"

Jenkins CI/CD

jenkins 自动化

!image-20250918142028443](/images/image-20250918142028443.png)

Jenkins 是一个开源的自动化部署工具，主要用于实现持续集成（CI）和持续部署（CD）流程，广泛应用于软件开发的自动化构建、测试、部署等环节。它由 Java 开发，支持跨平台运行（Windows、Linux、macOS 等），并通过丰富的插件生态系统扩展功能，适配各种开发语言、工具和环境。

核心功能

  1. 持续集成（CI）
    自动拉取代码仓库（如 Git、SVN）的更新，触发构建流程（编译代码、运行单元测试、代码质量检查等），快速反馈开发中的问题，确保团队协作时代码的集成质量。
  2. 持续部署（CD）
    在代码通过构建和测试后，自动将应用部署到开发、测试或生产环境，减少手动操作，提高发布效率和一致性。
  3. 自动化任务调度
    支持定时触发任务（如夜间构建），或通过代码提交、其他任务完成等事件触发，实现全流程自动化。
  4. 分布式构建
    可将构建任务分配到多台代理节点（Agent）执行，分担主节点压力，提升大型项目的构建速度。
  5. 插件生态
    拥有数千款插件，支持各种场景：代码管理（Git、GitHub、GitLab）、构建工具（Maven、Gradle、npm）、测试工具（JUnit、Selenium）、部署工具（Docker、Kubernetes、Ansible）等，几乎可适配所有主流开发栈。

基本架构

  • Jenkins 主节点（Master）：负责管理任务、调度构建、监控节点状态，提供 Web 界面供用户配置和操作。
  • 代理节点（Agent/Slave）：接收主节点分配的任务，实际执行构建、测试等操作，可在不同环境（如不同操作系统、不同依赖版本）中运行。

典型工作流程

  1. 开发者向代码仓库提交代码。
  2. Jenkins 监控到代码更新，自动触发预设的流水线（Pipeline）。
  3. 执行构建步骤：拉取代码 → 编译 → 运行单元测试 → 代码质量分析（如 SonarQube）。
  4. 构建成功后，自动部署到测试环境，触发集成测试。
  5. 测试通过后，可手动或自动部署到生产环境，并记录整个流程的日志和报告。

优势

  • 开源免费：无需付费即可使用核心功能和大部分插件。
  • 灵活可扩展：通过插件和自定义脚本适配复杂场景。
  • 易于上手：提供可视化 Web 界面，支持通过图形化配置或代码（Jenkinsfile）定义流水线。
  • 社区活跃：拥有庞大的用户和开发者社区，问题解决方案丰富，插件更新及时。

应用场景

  • 软件开发中的自动化构建、测试和部署。
  • 定期执行脚本任务（如数据备份、系统检查）。
  • 多环境（开发、测试、生产）的一致性部署管理。
  • 与 DevOps 工具链（如 Docker、K8s、GitLab、Prometheus）集成，构建完整的自动化体系。

Jenkins 流水线

CiCd jenkins

概念

Jenkins 流水线 (或简单的带有大写"P"的"Pipeline") 是一套插件，它支持实现和集成 continuous delivery pipelines 到 Jenkins。

continuous delivery (CD) pipeline是你的进程的自动表达，用于从版本控制向用户和客户获取软件。 你的软件的每次的变更 (在源代码控制中提交)在它被释放的路上都经历了一个复杂的过程 on its way to being released. 这个过程包括以一种可靠并可重复的方式构建软件, 以及通过多个测试和部署阶段来开发构建好的软件 (c成为 "build") 。

jenkins 支持流水线语法：

  • 声明式

  • 脚本化

声明式语法：

pipeline {
    agent any 
    stages {
       #定义build步骤
        stage('Build') { 
          #构建的过程
            steps {
                // 
            }
        }   
         #定义"Test" 阶段。
        stage('Test') { 
          执行与"Test" 阶段相关的步骤。
            steps {
                // 
            }
        }
        #定义"Deploy" 阶段。
        stage('Deploy') { 
          #执行与"Deploy" 阶段相关的步骤。
            steps {
                // 
            }
        }
    }
}

脚本式： Jenkinsfile

node {  
    stage('Build') { 
        // 
    }
    #定义"Test" 阶段
    stage('Test') { 
    #执行与"Test" 阶段相关的步骤
        // 
    }
    stage('Deploy') { 
        // 
    }
}

jenkins 安装插件：`docker

声明式流水线；

pipeline {
    agent any
    stages {
        stage('pull code') {
            steps {
               git branch: 'test', credentialsId: '0eec2047-599a-4ca9-b23a-b9e676562dfd', url: 'http://192.168.1.110/dev-group/jenkis-project.git'
                echo 'pull code成功'
            }
        }
        stage('docker build'){
            steps {
            sh 'docker  --version'              
            sh  'sudo docker build -t 192.168.1.101/httpd/tpd-example-web:v2 .'  
            sh  'sudo docker images'
            }
        }
        stage("login harbor"){
           steps {
               sh "sudo  docker login http://192.168.1.101 -u admin -p 'Harbor12345'"
           }
        }
        stage('docker push repo'){
            steps {
             sh  'sudo  docker push 192.168.1.101/httpd/tpd-example-web:v2'
            }
        }
        stage('部署'){
            steps{
               sh  'ansible all -m shell  -a  "docker pull  192.168.1.101/httpd/tpd-example-web:v2" '
               sh  'ansible all -m shell  -a "docker run  -d --name httpd-example  -p 80:80 192.168.1.101/httpd/tpd-example-web:v2 "'
               echo  "部署完成"
            }
        }
    }
}

脚本式：

node {
    stage('pull code'){
        git branch: 'test', credentialsId: '0eec2047-599a-4ca9-b23a-b9e676562dfd', url: 'http://192.168.1.110/dev-group/java-web-app.git'
    }
    stage('查看文件'){
       sh 'ls .'
    }
    stage('docker Build') {
       sh  'docker build . '
    }
    stage('test'){
        echo "test images"
    }
    stage('push  image  repo') {
       echo "push  images "
    }

    stage('Deploy') {
       echo "部署"
       when {
         branch 'development'
       }
    }
}
