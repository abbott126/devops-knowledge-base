Ubuntu 

# step 1: 安装必要的一些系统工具
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg

# step 2: 信任 Docker 的 GPG 公钥
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# Step 3: 写入软件源信息
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu \
  "$(. /etc/os-release && echo "$VERSION_CODENAME")" stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Step 4: 安装Docker
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 安装指定版本的Docker-CE:
# Step 1: 查找Docker-CE的版本:
# apt-cache madison docker-ce
#   docker-ce | 17.03.1~ce-0~ubuntu-xenial | https://mirrors.aliyun.com/docker-ce/linux/ubuntu xenial/stable amd64 Packages
#   docker-ce | 17.03.0~ce-0~ubuntu-xenial | https://mirrors.aliyun.com/docker-ce/linux/ubuntu xenial/stable amd64 Packages
# Step 2: 安装指定版本的Docker-CE: (VERSION例如上面的17.03.1~ce-0~ubuntu-xenial)

volume 数据卷

volume 是容器的持久数据存储，由 Docker 创建和管理。您可以使用 docker 命令docker volume create 创建卷，或者 Docker 可以在容器或服务创建期间创建卷。

创建卷时，它会存储在 Docker 主机上的一个目录中。将卷挂载到容器中时，该目录也会被挂载到容器中。这与绑定挂载的工作方式类似，不同之处在于卷由 Docker 管理，并且与主机的核心功能隔离。

何时使用卷

卷是持久化 Docker 容器生成和使用的数据的首选机制。 绑定挂载依赖于主机的目录结构和操作系统，而卷则完全由 Docker 管理。对于以下用例，卷是一个不错的选择：

  • 与绑定挂载相比，卷更容易备份或迁移。
  • 您可以使用 Docker CLI 命令或 Docker API 管理卷。
  • 卷可以在 Linux 和 Windows 容器上运行。
  • 卷可以在多个容器之间更安全地共享。
  • 新卷的内容可以通过容器或构建预先填充。
  • 当您的应用程序需要高性能 I/O 时。

卷的生命周期

卷的内容存在于给定容器的生命周期之外。当容器被销毁时，可写层也会随之销毁。使用卷可以确保即使使用该卷的容器被移除，数据也能持久保存。

给定的卷可以同时挂载到多个容器中。当没有正在运行的容器使用卷时，该卷仍然可供 Docker 使用，并且不会被自动删除。您可以使用 docker volume prune 删除未使用的卷。

命名卷和匿名卷

卷可以是命名的，也可以是匿名的。匿名卷会被赋予一个随机名称，该名称保证在给定的 Docker 主机中是唯一的。与命名卷一样，即使删除了使用它们的容器，匿名卷也会保留，除非在创建容器时使用 --rm 标志，在这种情况下 与容器关联的匿名卷被销毁的情况。请参阅 删除匿名卷 。

使用卷：

要使用 docker run 命令挂载卷，您可以使用 --mount 或 --volume 标志

docker run --mount type=volume,src=<volume-name>,dst=<mount-path>
docker run --volume <volume-name>:<mount-path>

Example:

[root@docker ~]# docker run  -d   --name  nginx_volume  --mount  source=nginx-data,target=/app  nginx-proxy:v1

Dockerfile

Dockerfile 是构建镜像的文件

一切都从 Dockerfile 开始。

Docker 通过读取 Dockerfile 中的指令来构建镜像。 Dockerfile 是一个文本文件，其中包含构建源的说明 代码。Dockerfile 指令语法由规范定义 参考 Dockerfile 参考 。

Dockerfile 语法：

FROM  #指定哪一个镜像为基础镜像
RUN   #执行构建命令
COPY  #复制文件和目录
ADD   #
ENV   #设置环境变量
WORKDIR #指定工作目录
EXPOSE  #描述您的应用程序正在监听的端口
MAINTAINER #作者新版不维护；1.13版本之后不在维护推荐使用label
CMD ["/usr/sbin/httpd", "-D", "FOREGROUND"]
ENTRYPOINT
特性 ENTRYPOINT CMD
主要作用 将容器定义为可执行程序 为容器提供默认命令和参数
是否易被覆盖 难（需 --entrypoint） 易（docker run 后的命令直接覆盖）
推荐使用形式 ENTRYPOINT ["exec", ...] CMD ["arg1", "arg2"]
如何选择 当你想让容器像一个命令一样工作时使用（如 docker run my-app）。 当你想为容器提供默认行为，且希望该行为容易被覆盖时使用。

Example: Dockerfile

# 使用CentOS 8作为基础镜像
FROM centos:centos8

# 添加镜像元数据，版本信息
LABEL version="1.0"
LABEL description="CentOS 8 with httpd, JDK 21, vim and net-tools"

# 移除默认的yum仓库配置（CentOS 8已停止维护，需要使用Vault仓库）
RUN rm -rf /etc/yum.repos.d/*

# 添加阿里云的CentOS 8 Vault仓库（适用于已停止维护的CentOS 8）
RUN curl -o /etc/yum.repos.d/CentOS-Base.repo https://mirrors.aliyun.com/repo/Centos-vault-8.5.2111.repo

# 检查仓库列表是否正常
RUN dnf repolist

# 安装vim编辑器
RUN dnf -y install vim

# 安装网络工具（如ifconfig等）
RUN dnf -y install net-tools

# 安装httpd web服务器
RUN dnf -y install httpd

# 复制JDK安装包到容器当前目录（建议指定更明确的路径）
COPY jdk-21_linux-x64_bin.tar.gz /tmp/

# 解压JDK到/usr/local目录（通常软件安装在/usr/local下）
ADD jdk-21_linux-x64_bin.tar.gz

# 配置JDK环境变量（注意：解压后的目录名需与实际一致）
ENV JAVA_HOME=/usr/local/jdk-21.0.8
ENV PATH=$PATH:$JAVA_HOME/bin

# 创建并挂载数据卷（用于持久化数据）
VOLUME /app          # 应用程序目录
VOLUME /opt/abc      # 额外数据目录

# 设置工作目录为/app
WORKDIR /app

# 复制index.html到当前工作目录（即/app下）
COPY index.html .

# 设置入口点为bash交互shell（方便进入容器操作）
ENTRYPOINT ["/bin/bash"]

# 暴露80端口（httpd默认端口），而非22端口（未安装ssh服务）
EXPOSE 80/tcp

# 如需启动httpd，可使用以下CMD（取消注释并注释上面的ENTRYPOINT）
CMD ["/usr/sbin/httpd", "-D", "FOREGROUND"]

/usr/sbin/httpd

  • 这是 Apache HTTP 服务器的可执行文件路径

  • 在 CentOS/RHEL 系统中，httpd 的二进制文件通常位于此路径

  • -D 参数

  • 这是 Apache 的定义参数，用于在启动时设置特定的配置指令

  • 它可以指定要启用的模块或特定的服务器配置

  • FOREGROUND

  • 这是 -D 参数的值，也是最关键的部分

  • 它告诉 Apache 在前台运行，而不是作为守护进程（daemon）在后台运行

Docker compose

Docker Compose 是一个用于定义和运行多容器 Docker 应用程序的工具。它使用 YAML 文件来配置应用程序的服务、网络、数据卷等，然后通过一个简单的命令就能启动整个应用栈。

核心概念

  • 单机编排：主要针对单台主机上的多容器应用
  • 声明式配置：使用 YAML 文件描述整个应用架构
  • 一键操作：一条命令启动/停止所有服务

主要配置项

配置项 说明 示例
version Compose 文件版本 '3.8'
services 定义各个服务容器 web, db, cache
networks 自定义网络配置 backend, frontend
volumes 数据卷配置 db_data, app_logs

Example:

[root@docker httpd-example]# cat   docker-compose.yaml 
version: v1
services:
  web:
    build: .   #当前目录必须有Dockerfile
    ports:
      - "33000:80"

dockercompose命令：

[root@docker httpd-example]# docker compose --help
[root@docker httpd-example]# docker compose  up    #构建并前台运行
[root@docker httpd-example]# docker compose  up -d  #构建完成并后台运行
[root@docker httpd-example]# docker compose  stop  #停止所有的容器（docker-compose.yaml）
[root@docker httpd-example]# docker compose  start #运行所有的容器（docker-compose.yaml）

Harbor

Harbor 是一个开源镜像仓库，它通过策略和基于角色的访问控制来保护工件，确保镜像经过扫描且无漏洞，并将镜像签名为可信镜像。Harbor 是一个 CNCF 毕业项目，提供合规性、性能和互操作性，帮助您在 Kubernetes 和 Docker 等云原生计算平台上一致且安全地管理工件。
