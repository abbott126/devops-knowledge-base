Redis 数据库类型

官方文档地址：https://redis.io/docs/latest/develop/data-types/

Redis是一个数据结构服务器。Redis的核心是提供本地数据类型的集合，帮助您解决从缓存到排队再到事件处理的各种问题。以下是每种数据类型的简短描述，并带有更广泛的概述和命令引用的链接。每个概述都包含一个包含代码示例的综合教程

字符串数据类型

Redis⽀持五种数据类型：String（字符串），Hash（哈希），List（列表），Set（集合）及Zset(sorted set：有序集合)。

1.2、字符串简介

字符串类型是redis最基础的数据结构，⾸先键是字符串类型，⽽且其他⼏种结构都是在字符串类型基础上构建

的，所以字符串类型为其他四种数据结构尊定了基础。

字符串类型实际上可以是简单的字符串、复杂的字符串（xml、json）、数字（整数、浮点数）、⼆进制（图⽚、

⾳频、视频）。

1.3、字符串应⽤场景

共享session：

⽤户登录后，⽤户刷新⼀次可能会重复登录，这个时候我们就将⽤户session集中管理，在这种模式下每次获取和

更新⽤户信息都可以从redis中获取。

限速：

当我们在登录时，⽤来限制为我⼿机接到验证码的时间，防⽌我们的短信接⼝不被频繁访问，会限制⽤户每分钟获

取验证码的频率。

⼆、字符串命令

  • SET存储一个字符串值。
  • MSET 存储多个字符串key和value
  • SETNX仅在密钥尚未存在的情况下存储字符串值。对实施锁很有用。
  • GET检索字符串值。
  • MGET在一次操作中检索多个字符串值

三、 语法：

set key value [EX seconds] [PX milliseconds] [NX|XX]
将字符串值 value 关联到 key

注意：

  • EX:设置键的过期时间为 second 秒
  • PX:设置键的过期时间为 millisecond 毫秒
  • NX:只在键不存在时，才对键进⾏设置操作。
  • XX:只在键已经存在时，才对键进⾏设置操作。

Example: 

192.168.137.111:6379[4]> set "183001002516" 123  EX 30
OK


192.168.137.111:6379[4]> KEYS  * 
183001002516
# 设置key的值：过期时间为30秒 如何值key的值不存在则不设置否则设置
192.168.137.111:6379[4]> set "18301002516" 456  Ex  30  NX  
OK


192.168.137.111:6379[4]> set "18301002516" 789  Ex  30  NX    返回为空；则表示key的值还存在

192.168.137.111:6379[4]> get 18301002516
456


192.168.137.111:6379[4]> setex  "18301002516" 789    30  NX

注意：

因为 SET 命令可以通过参数来实现和 SETNX 、 SETEX 和 PSETEX 三个命令的效果:

  • SETNX:若给定的 key 已经存在，则 SETNX 不做任何动作
  • SETEX:如果 key 已经存在， SETEX 命令将覆写旧值。
  • PSETEX:这个命令和 SETEX 命令相似，但它以毫秒为单位设置 key 的⽣存时间，⽽不是像 SETEX 命令那样，以秒为单位。

整数类型

  • INCR

将存储在key上的数字增加一。如果密钥不存在，则在执行操作之前将其设置为0。如果密钥包含错误类型的值或包含无法表示为整数的字符串，则返回错误。此操作仅限于64位有符号整数。

注意：这是一个字符串操作，因为Redis没有专用的整数类型。存储在键上的字符串被解释为基数-10 64位有符号整数来执行操作。

Redis在其整数表示中存储整数，因此对于实际包含整数的字符串值，存储整数的字符串表示没有开销。

语法：INCRBY key

192.168.137.111:6379> get id2
1
192.168.137.111:6379> INCR  id2
2
192.168.137.111:6379> INCR  id2
3

数据持久化

https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/

Redis 如何将数据写入磁盘持久性是指将数据写入持久存储，例如固态磁盘 （SSD）。Redis 提供了一系列持久化选项。这些包括：

  • RDB (Redis Database): RDB persistence performs point-in-time snapshots of your dataset at specified intervals.
**RDB**（Redis 数据库）：RDB 持久化按指定的时间间隔对数据集执行时间点快照。
  • AOF (Append Only File): AOF persistence logs every write operation received by the server. These operations can then be replayed again at server startup, reconstructing the original dataset. Commands are logged using the same format as the Redis protocol itself.
**AOF**（仅追加文件）：AOF 持久性记录服务器收到的每个写入作。然后可以在服务器启动时再次重放这些作，从而重建原始数据集。使用与 Redis 协议本身相同的格式记录命令。
  • No persistence: You can disable persistence completely. This is sometimes used when caching.
**无持久性** ：您可以完全禁用持久性。有时在缓存时使用这。
  • RDB + AOF: You can also combine both AOF and RDB in the same instance.
**RDB + AOF**：您还可以在同一实例中组合 AOF 和 RDB。

配置RDB自动持久化

#快照的管理
################################ SNAPSHOTTING   ################################
#根据规则实现自动`bgsave`
save  3600 1     #当 3600s 内如果有 1次 Redis 键值发生改变，就会触发持久化；
save  300  100   #当 300s 内如果有 100次 Redis 键值发生改变，就会触发持久化；
save  60   1000  #当 60 内如果有 1000次 Redis 键值发生改变，就会触发持久化；
#最近一次后台保存操作失败，Redis 将停止接受写入请求。
stop-writes-on-bgsave-error yes
#是否开启数据的压缩 默认是开启的状态；基于LZF的压缩算法
rdbcompression yes
#是否在文件中增加校验值
rdbchecksum yes
#定义备份的文件名称；.rdb
dbfilename dump.rdb

#定义文件存放的目录
dir ./

############################## APPEND ONLY MODE ###############################

appendfilename "appendonly.aof"  #定义文件的名称

#缓冲区同步策略
# appendfsync always

# appendfsync no
#是否重写，默认不重写
no-appendfsync-on-rewrite no   

#重写规则
auto-aof-rewrite-percentage 100  #AOF 自动重写的 “增长率阈值”。
auto-aof-rewrite-min-size 64mb   # AOF 自动重写的 “最小文件大小阈值”。
aof-load-truncated yes #当 AOF 文件尾部被截断（不完整）时，是否允许 Redis 加载该文件？
默认值为 yes（允许）。

aof-use-rdb-preamble yes
> Redis 可以用 RDB 或 AOF 格式创建 AOF 的 “基础文件”。使用 RDB 格式始终更快、更高效，禁用此选项仅为兼容旧版本

aof-timestamp-enabled no
> Redis 支持在 AOF 中记录时间戳注解，以实现 “从特定时间点恢复数据” 的功能。但启用此功能会改变 AOF 格式，可能与现有 AOF 解析工具不兼容。 默认值为 no（禁用）

always：客户端的每一个写操作都保存到aof文件当中，这种策略很安全，但是每个写都会有IO操作，所以也很慢。

appendonly.aof.manifest 文本格式 AOF 混合文件的 “清单文件”，记录基础文件、增量文件的元信息，用于 Redis 加载时识别
