proxySQL

在现代数据库管理的动态环境中，优化性能和有效处理数据库流量是各种规模企业最关心的问题。ProxySQL 是一种强大的 SQL 代理解决方案，充当数据库客户端和服务器之间的关键桥梁，提供大量旨在简化数据库作的功能。

ProxySQL 不仅仅是数据库管理员武器库中的另一个工具，它还是游戏规则的改变者。凭借其智能路由查询、平衡负载和提供故障转移处理的能力，ProxySQL 使组织能够充分利用其数据库基础设施的潜力。无论您是在努力应对可扩展性挑战、努力提高性能还是寻求确保高可用性，ProxySQL 都是一个多功能的盟友，能够满足各种数据库环境的多样化需求。

添加路由规则

#查询的规则
proxysql_Admin> INSERT INTO mysql_query_rules (rule_id, active, match_digest, destination_hostgroup, apply)VALUES (1, 1, '^SELECT.*|^SHOW.*', 20, 1); 
Query OK, 1 row affected (0.00 sec)


#写入规则
proxysql_Admin> INSERT INTO mysql_query_rules (rule_id, active, match_digest, destination_hostgroup, apply)VALUES (2, 1, '^INSERT|^UPDATE|^DELETE|^CREATE', 10, 1);
Query OK, 1 row affected (0.00 sec)

保存规则：

#将规则添加到运行时
proxysql_Admin> LOAD MYSQL QUERY RULES TO RUNTIME;
Query OK, 0 rows affected (0.00 sec)

#将规则保存的磁盘中
proxysql_Admin> SAVE MYSQL QUERY RULES TO DISK;
Query OK, 0 rows affected (0.05 sec)

文档地址：

ONLINE: 后端服务器全面运行
SHUNNED:  后端服务器暂时停止使用，因为时间太短，连接错误过多，或者复制延迟超过允许的阈值

OFFLINE_SOFT:
    当服务器进入 OFFLINE_SOFT 模式时，不会向该服务器创建新连接，而现有连接将保留，直到它们返回到连接池或被销毁。换句话说，连接将保持使用状态，直到再次启用多路复用，例如当事务完成时。只要多路复用有效，就可以优雅地分离后端

OFFLINE_HARD
当服务器进入 OFFLINE_HARD 模式时，不会向该服务器创建新连接，并且会立即丢弃现有的空闲连接，而当前与客户端会话关联的后端连接会在客户端尝试使用它们时立即被丢弃。这相当于从主机组中删除服务器。在内部，将服务器设置为 OFFLINE_HARD 状态相当于删除服务器
