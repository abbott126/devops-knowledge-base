Ceph 简化版

ceph 分布式存储

前言

Ceph 是一款分布式存储系统，支持三种存储方式：对象存储、块存储和文件存储。Ceph 的部署工具有很多，但是 Ceph v15.2 (Octopus) 开始，推荐使用 cephadm 和 rook。其中 rook 是针对 kubernetes 的 ceph 部署工具，不在本例范围。

cephadm 为单独部署工具，使用容器化技术进行集群部署和管理，容器技术目前支持使用 docker 和 podman，本例以 podman 为例进行部署。本例以 Ceph v16.2 (Pacific) 为例进行安装演示。
警告：

由于 Ceph 自带的 Ingress 还在开发，虽然可以配置成功，但是不能平滑切换，高可用 NFS 可能要等到 Ceph v17.2 (Quincy) 实现，如果真的可以，到时再测试一下。具体说法可以参考官方文档

一、环境说明

Rocky 8（Minimal Install） 
cat /etc/system-release
Rocky Linux release 8.10 (Green Obsidian)
提示：

Ceph 分布式存储集群中一般分为两种类型主机: MON （Monitor）监控节点 和 OSD (Object Storage Device) 对象存储设备节点。Ceph 存储集群最少需要一个 MON 和 两个 OSD （作为复制）组成。
警告： 生产环境里一般 MON 节点是 3 或 5 个， OSD 节点是越多越好，而且这两种节点应在不同主机安装，但是本例为实验目的，就安装在一起了。

主机的分配

HostName IP addr cpu Disk Disk Role
ceph1 192.168.19.136 2 Sda,sdb MON,OSD
ceph2 192.168.19.137 2 Sda,sdb OSD
ceph3 192.168.19.138 2 Sda,sdb OSD
⚠️ 警告：

每个虚拟机配置两块网卡（一块 NIC 设置为 NAT，另一块 NIC 设置为 Host-only）。
    1. 使用 NAT 网络，虚拟机可以访问外网，下载安装包。

    2. 使用 Host-only 的好处是虚拟机网络不会受外界的网络变化影响.
注意： 这是一个信息提示框。
  • 操作系统安装到 sda 盘上。
  • sdb 盘不需要格式化，因为 cephadm 只支持 BlueStore OSDs 就是直接管理裸设备，这样会极大的提升性能。
  • Ceph 支持管理网络和公用网络分开，本例没有设置，使用同一个网络。

  1. 再另外两个节点设置与 ceph1 时间进行同步
[root@ceph2/3 ~]# vi /etc/chrony.conf
# Use public servers from the pool.ntp.org project.

  • 如果是 `ceph1;ceph2;ceph3`，表示直接显示了所在的主机位置。

管理 OSD

添加 OSD 需要满足以下所有条件：
  • 设备必须没有分区。
  • 设备不得具有任何 LVM 状态。
  • 不得安装设备。
  • 该设备不得包含文件系统。
  • 该设备不得包含 Ceph BlueStore OSD。
  • 设备必须大于 5 GiB。

## 三、Ceph 存储类型与使用 ### 1. Ceph 的三大存储类型 | 存储类型 | 接口名称 | 特点与用途 | | -------- | -------- | ---------------------------------------------- | | 块存储 | RBD | 提供类似磁盘的虚拟块设备，适用于虚拟机、数据库 | | 对象存储 | RGW | 支持 S3/Swift 接口，适合备份、大文件、云服务 | | 文件系统 | CephFS | 类似 NFS 的 POSIX 文件系统，适合共享文件服务 | ### 块存储（RBD） - RBD 原理与使用场景 - 创建、挂载与格式化 RBD 镜像 - RBD 快照与克隆 - RBD 映射到本地/虚拟机（KVM） #### **RBD 原理与使用场景**
RBD（RADOS Block Device）是 Ceph 提供的一种 高性能、可扩展、分布式的块存储解决方案，它将块设备（类似硬盘）直接构建在 Ceph 的对象存储（RADOS）之上。它适合于虚拟机磁盘、数据库等对性能和可靠性要求较高的场景。

[root@ceph1 ~]# ceph osd pool create mynfs_data

[root@ceph1 ~]# ceph osd pool application enable mynfs_data nfs
#### 新建 NFS 集群 1. 创建集群, 使用 `ceph nfs cluster create` 命令 
[root@ceph1 ~]# ceph nfs cluster create mynfs 3 --ingress --virtual_ip 192.168.19.18
> `注意` > 本例使用了 `--ingress` 参数，目前 ingress 的高可用还没有完全完成，等到 `Ceph Quincy` 发布才支持 这个命令会新建两个编排服务 `ingress.nfs.mynfs` 和 `nfs.mynfs` 2. 查看一下 
[root@ceph1 ~]# ceph nfs cluster ls

ceph orch ls --service-name nfs.mynfs --export > nfs.mynfs.yaml
> 删除 NFS 集群，以下两种方法： - 方法 1 使用 `ceph nfs cluster rm ` 命令 
ceph nfs cluster rm mynfs
- 方法 2 使用 `ceph orch rm` 删除 
[root@ceph1 ~]# ceph orch rm ingress.nfs.mynfs

[root@ceph1 ~]# ceph orch rm nfs.mynfs
Removed service nfs.mynfs
#### 新建 CephFS 的 nfs 导出 
[root@ceph1 ~]# ceph nfs export create cephfs --cluster-id mynfs --pseudo-path /data --fsname myfs --squash no_root_squash
查看 nfs 信息 
[root@ceph1 ~]# ceph nfs export info mynfs /data
> 也可以在 Ceph Dashboard 中新建 NFS，但在 Dashboard 中和 CLI 中的新建的，查看最后参数不一样，Dashboard 的多一些。 #### 客户端配置 参考 [NFS MOUNTING](https://docs.ceph.com/en/pacific/mgr/nfs/#mounting) > `注意` > 只支持 NFS v4.0+ 的协议 挂载的命令 
mount -t nfs -o nfsvers=4.1,proto=tcp <ganesha-host-name>:<ganesha-pseudo-path> <mount-point>
本例如下： 
[root@cephclient1 ~]# mount -t nfs  192.168.19.18:/data /mnt
这样客户端就将存储中的 /data 挂载到了本地 /mnt 目录 卸掉挂载 
[root@cephclient1 ~]# umount /mnt
