OpenStack 简介

OpenStack 是一个开源的云计算平台，主要用于构建和管理公有云和私有云环境。它由一系列相互关联的服务组件组成，可以管理大量的计算资源、存储资源和网络资源。

核心特点

  • 开源：代码完全公开，允许自由修改和定制
  • 可扩展：从几台服务器到数千台服务器的集群都能支持
  • 灵活：支持多种虚拟化技术（KVM、VMware、Xen 等）
  • 模块化：由多个独立服务组成，可按需部署
  • 企业级：被许多大型企业、云服务提供商采用

逻辑架构

各服务组件的功能如下：

  • Keystone: 为各服务组件提供用户认证和权限验证功能；
  • Ceilometer: 为各服务组件提供监控、检索和计量功能；
  • Horizon: 为用户操作 OpenStack 项目中的各服务提供基于Web形式的图形界面；
  • Glance: 为虚拟机实例提供镜像服务，Glance服务中的镜像介质存放在Swift中；
  • Neutron: 为虚拟机实例提供网络连接服务，同时也为lronic 提供PXE网络;
  • lronic: 提供物理机的添加、删除、电源管理和安装部署等功能；
  • Nova: 为虚拟机实例提供计算资源；
  • Trove: 为虚拟机镜像提供注册服务；使用Nova 启动数据库实例；依附虚拟实例，提供数据存储、操作和管理；可以备份数据库实例到Swift 中；
  • Cinder: 为虚拟机实例提供块设备，同时备份设备数据到Swift 中；
  • Sahara: 通过Heat编排集群配置；在Swift 中保存或二进制文件；将任务分配给虚拟机实例处理；通过Nova 运行数据处理实例；在Glance 中注册Hadoop 镜像;
  • Heat: 可以编排Cinder Neutron Glance和 Nova 各种资源;

Memcached 介绍

免费开源，高性能，分布式内存对象缓存系统 ，本质上是通用的，但旨在通过减轻数据库负载来加速动态 Web 应用程序。

Memcached 是一个内存中的键值存储，用于存储来自数据库调用、API 调用或页面渲染结果的任意数据（字符串、对象）的小块。

Memcached 简单而强大 。其简单的设计促进了快速部署、易于开发，并解决了大型数据缓存面临的许多问题。它的 API 可用于大多数流行语言

opnstack 使用memcached的作用

服务的 Identity 服务身份验证机制使用 Memcached 来缓存令牌。memcached 服务通常在控制器节点上运行。对于生产部署，我们建议启用防火墙、身份验证和加密的组合来保护它

六、Etcd 数据库

一种分布式的、可靠的键值存储，用于存储分布式系统中最关键的数据

etcd 是一个强一致的分布式键值存储， 提供了一种可靠的方式来存储需要由 分布式系统或机器集群。它优雅地处理领导者 在网络分区期间进行选举，并且可以容忍机器故障，甚至 在 leader 节点中。

在openstack 中的作用：

OpenStack 服务可以使用 Etcd，这是一种分布式可靠的键值存储，用于分布式密钥锁定、存储配置、跟踪服务存活率和其他场景。

在 OpenStack 云平台中，etcd 是一个关键的分布式键值存储组件，主要用于存储和管理集群中的配置数据、状态信息以及协调分布式服务。它凭借强一致性、高可用性和分布式特性，成为 OpenStack 部分核心服务的 “数据大脑”。

Install OpenStack services

1. Identity service部署身份认证服务

keystone组件

OpenStack 系统由几个单独安装的关键服务组成。这些服务根据您的云需求协同工作，包括计算、身份、网络、图像、块存储、对象存储、远程监控、演示和数据库服务。您可以单独安装这些项目中的任何一个，并将它们配置为独立或连接的实体。

文档地址：https://docs.openstack.org/keystone/2024.1/install/

概述：

OpenStack Identity 服务为管理身份验证、授权和服务目录提供了单点集成。

Identity 服务通常是用户与之交互的第一个服务。一旦通过身份验证，最终用户就可以使用他们的身份访问其他 OpenStack 服务。同样，其他 OpenStack 服务也利用身份服务来确保用户是他们所说的那个人，并发现其他服务在部署中的位置。身份服务还可以与某些外部用户管理系统（如 LDAP）集成。

用户和服务可以通过使用服务目录来定位其他服务，服务目录由 Identity 服务管理。顾名思义，服务目录是 OpenStack 部署中可用服务的集合。每个服务可以有一个或多个端点，每个端点可以是以下三种类型之一：admin、internal, or public。在生产环境中，出于安全原因，不同类型的端点可能驻留在向不同类型的用户公开的单独网络上

2、images service Glance

OpenStack Image Service（通常称为 Glance）是 OpenStack 云平台的核心组件之一，主要负责虚拟机镜像的管理，包括镜像的存储、查询、注册和分发等功能。它为 OpenStack 中的计算服务（Nova）提供虚拟机启动所需的镜像资源，是构建和管理云环境的基础组件。

Glance 作为 OpenStack 的 “镜像仓库”，简化了虚拟机镜像的生命周期管理，是构建弹性、可扩展云环境的关键组件。

核心功能

1. 镜像管理
  • 支持镜像的上传、下载、创建、删除、更新等操作。
  • 允许为镜像添加元数据（如操作系统类型、架构、最小磁盘 / 内存要求等），方便用户检索和使用。
2. 多存储后端支持
  • 可对接多种存储类型，包括本地文件系统、对象存储（如 Swift）、块存储（如 Cinder）、分布式文件系统（如 Ceph）等，灵活适配不同的存储需求。
3.镜像格式兼容
  • 支持常见的虚拟机镜像格式，如 QCOW2（KVM 默认格式）、RAW、VMDK（VMware）、VHD（Hyper-V）等，实现跨平台镜像的复用。
4. 访问控制
  • 结合 OpenStack 的身份认证服务（Keystone），实现镜像的权限管理（如私有镜像、项目内共享、公共镜像）。
5. 镜像分发优化
  • 支持镜像缓存和复制机制，提升大规模部署时的镜像分发效率，减少网络带宽压力。

核心组件与架构

Glance 的架构主要包括以下组件：

  1. Glance API
  2. 提供 RESTful API 接口，接收用户或其他服务（如 Nova）的请求（如上传镜像、查询镜像列表）。
  3. 负责请求验证、权限检查和元数据管理。
  4. Glance Registry（已 deprecated）
  5. 早期版本中用于单独管理镜像元数据的服务，现元数据功能已整合到 Glance API 中，不再推荐使用。
  6. 存储后端（Store Backends）
  7. 实际存储镜像数据的组件，支持多种存储类型（如本地文件、Swift、Ceph 等），通过统一的接口与 Glance API 交互。
  8. 数据库
  9. 存储镜像的元数据（如 ID、名称、状态、创建时间等），不存储镜像本身的数据。

典型工作流程

  1. 用户通过 Glance API 上传镜像（或从外部导入），并指定镜像格式、元数据等信息。
  2. Glance 将镜像元数据存入数据库，同时将镜像数据写入配置的存储后端。
  3. 当 Nova 需要创建虚拟机时，通过 Glance API 查询并获取指定镜像。
  4. Glance 从存储后端读取镜像数据，提供给 Nova 用于虚拟机实例的创建。

应用场景

  • 为云平台用户提供标准化的操作系统镜像（如 Linux、Windows）。
  • 支持用户自定义镜像（如预装了特定软件的虚拟机快照），实现快速部署。
  • 结合镜像版本管理，支持镜像的迭代更新和回滚。

3. Placement service

OpenStack Placement Service（放置服务）是 OpenStack 云平台中的核心组件之一，主要负责跟踪和管理计算资源的库存与使用情况，并为虚拟机实例（Instance）的创建提供最优的资源分配决策支持。

Placement Service 是 OpenStack 实现灵活、高效资源调度的基础，尤其在大规模和异构资源环境中至关重要。

核心定位

在早期的 OpenStack 版本中，资源调度逻辑集成在计算服务（Nova）中，随着云平台规模扩大和资源类型多样化（如 GPU、FPGA、本地磁盘等），单独拆分出 Placement Service，专门处理：

  1. 资源的 ** inventory（库存）** 记录：跟踪各计算节点的资源总量（如 CPU 核心数、内存大小、磁盘容量、特殊硬件等）。
  2. 资源的 ** allocation（分配）** 管理：记录已分配给虚拟机的资源，计算剩余可用资源。
  3. 为 Nova 调度器提供资源查询接口：帮助确定哪个计算节点最适合创建新的虚拟机。

核心功能

  1. 统一资源建模

支持对多种类型的资源进行标准化描述，包括：

  • 基础资源：VCPU（虚拟 CPU）、内存（RAM）、磁盘（Disk）。
  • 特殊硬件资源：GPU、FPGA、NIC（网络接口卡）、本地 SSD 等。

  • 自定义资源：可根据需求扩展（如硬件加密卡、特定处理器型号等）。

  • 资源跟踪与统计

  • 每个计算节点（Nova Compute）会定期向 Placement Service 上报自身的资源库存和使用情况。

  • 提供 API 接口查询特定资源的分布（如 “哪些节点有 GPU 资源？”“某节点剩余内存多少？”）。

  • 资源分配管理

  • 当创建虚拟机时，Placement Service 记录资源分配关系（哪个虚拟机占用了哪个节点的哪些资源）。

  • 当虚拟机销毁时，自动释放分配的资源，更新库存数据。

  • 辅助调度决策

  • 为 Nova 的调度器（Filter Scheduler 等）提供精确的资源数据，帮助筛选出满足条件的计算节点。

  • 支持基于资源需求的查询（如 “找一个至少有 2 核 VCPU、4GB 内存的节点”）。

核心术语

  • Resource Provider（资源提供者）：提供可分配资源的实体，通常是计算节点（Compute Node），也可以是共享存储、网络设备等。
  • Resource Class（资源类）：资源的类型分类，如VCPU、MEMORY_MB、DISK_GB、NVIDIA_GPU等。
  • Trait（特性）：资源的属性描述（非数量型），如 “支持硬件虚拟化”（HW_CPU_X86_VMX）、“磁盘是 SSD”（STORAGE_DISK_SSD）等。
  • Allocation（分配）：记录资源提供者向某个消费者（如虚拟机）分配的资源量。

工作流程（以创建虚拟机为例）

  1. 用户请求创建虚拟机，指定资源需求（如 2VCPU、4GB 内存、1 块 GPU）。
  2. Nova API 接收请求后，调用 Nova 调度器。
  3. 调度器向 Placement Service 查询：“哪些资源提供者（计算节点）有足够的VCPU=2、MEMORY_MB=4096、NVIDIA_GPU=1资源？”
  4. Placement Service 返回符合条件的节点列表及资源详情。
  5. 调度器从候选节点中选择最优节点，指示该节点上的 Nova Compute 创建虚拟机。
  6. 虚拟机创建成功后，Nova 通知 Placement Service 记录资源分配信息（更新该节点的可用资源）。

为什么需要 Placement Service？

  • 资源管理精细化：支持复杂资源类型（如 GPU）的调度，满足 AI、高性能计算等场景需求。
  • 提高资源利用率：通过精确的资源跟踪，避免过度分配或资源浪费。
  • 架构解耦：将资源管理逻辑从 Nova 中分离，使各组件职责更清晰，便于独立升级和扩展。

4. 计算节点：

OpenStack Compute Service（通常称为 Nova）是 OpenStack 云平台的核心组件，主要负责虚拟机（VM）的全生命周期管理，是实现 “计算即服务（IaaS）” 的核心支撑。

一、核心定位与作用

Nova 不直接提供硬件虚拟化能力（依赖 KVM、Xen、VMware 等虚拟化技术），而是通过统一接口对计算资源进行调度和管理，核心作用包括：

  1. 虚拟机生命周期管理：创建、启动、停止、重启、删除虚拟机，以及调整虚拟机规格（CPU、内存、磁盘）。
  2. 计算资源调度：根据预设策略（如资源利用率、负载均衡、亲和性规则），将虚拟机调度到合适的物理节点（Compute Node）。
  3. 资源抽象与分配：将物理服务器的 CPU、内存、存储等硬件资源抽象为可分配的 “计算资源”，按需分配给虚拟机。
  4. 与其他组件协同：对接网络（Neutron）、存储（Cinder、Swift）、身份认证（Keystone）等组件，为虚拟机提供完整的网络和存储能力。

二、核心架构与组件

Nova 采用分布式架构，主要由以下服务和节点组成，各组件通过消息队列（RabbitMQ）通信：

组件 / 节点 核心功能
控制节点（Controller Node） 运行 Nova 核心服务，负责接收请求、调度和管理，不直接运行虚拟机。
Nova API 对外提供 REST API 接口，是所有 Compute 服务请求的入口（如创建虚拟机、查询状态）。
Nova Scheduler 调度器，根据 “过滤规则”（如资源满足度）和 “权重策略”（如负载最低）选择目标物理节点。
Nova Conductor 代理控制节点与计算节点的数据库操作，避免计算节点直接访问数据库，提升安全性和性能。
Nova Cert 管理虚拟机访问的证书（如用于 VNC 连接的证书），部分版本已简化或集成。
计算节点（Compute Node） 运行虚拟机的物理服务器，负责虚拟机的实际创建和运行。
Nova Compute 计算节点上的核心服务，通过 “虚拟化驱动”（如 libvirt 驱动对接 KVM）创建和管理虚拟机。
虚拟化驱动（Driver） 适配不同虚拟化技术（KVM、Xen、VMware、LXC 等），屏蔽硬件差异，提供统一接口。

三、关键功能特性

  1. 多虚拟化技术支持：兼容主流虚拟化方案，默认推荐 KVM（开源、高性能），也支持 VMware vSphere、XenServer 等商业方案。
  2. 弹性伸缩（Auto Scaling）：结合 OpenStack Heat（编排服务）或第三方工具，根据负载自动增减虚拟机数量（如 CPU 使用率过高时扩容）。
  3. 高可用性（HA）：支持虚拟机迁移（冷迁移、热迁移）、计算节点故障时的虚拟机重建，减少服务中断时间。
  4. 资源隔离与限制：通过 CPU 配额、内存限制、磁盘 IO 限流等机制，避免单个虚拟机过度占用物理资源，保障多租户环境的稳定性。
  5. 远程访问：支持 VNC、SPICE 等协议，提供虚拟机的远程控制台访问，方便运维和用户操作。

四、典型工作流程（创建虚拟机）

以用户通过 Dashboard 或 API 创建虚拟机为例，Nova 的核心流程如下：

  1. 用户发送 “创建虚拟机” 请求（指定规格、镜像、网络等），经 Keystone 认证后提交给 Nova API。
  2. Nova API 验证请求合法性，将任务通过消息队列发送给 Nova Scheduler。
  3. Nova Scheduler 执行 “过滤”（筛选出满足资源需求的计算节点）和 “权重计算”（选择最优节点），确定目标计算节点。
  4. 目标计算节点上的 Nova Compute 接收到任务，通过虚拟化驱动（如 libvirt）创建虚拟机，并挂载网络（Neutron）和存储（Cinder）资源。
  5. 虚拟机创建完成后，Nova Compute 将状态同步到数据库，Nova API 向用户返回 “创建成功” 的响应。

五、与其他 OpenStack 组件的依赖关系

Nova 无法独立工作，必须依赖以下组件实现完整功能：

  • Keystone：提供身份认证和权限管理（如验证用户是否有权创建虚拟机）。
  • Neutron：为虚拟机提供网络连接（如分配 IP 地址、创建虚拟网卡）。
  • Glance：提供虚拟机镜像管理（Nova 从 Glance 下载镜像用于创建虚拟机）。
  • Cinder/Swift：提供持久化存储（Cinder 提供块存储，Swift 提供对象存储）。
  • Placement：负责计算资源的精细化管理和调度（如统计各节点的 CPU、内存剩余量）。

简单来说，Nova 是 OpenStack 云平台的 “计算引擎”，用户对虚拟机的所有操作都通过 Nova 实现，它也是连接硬件资源和用户需求的核心桥梁。

5. Networking service (neutron)

在 OpenStack（开源云基础设施管理平台）中，网络服务（Networking Service） 是核心组件之一，其官方项目名称为 Neutron。它的核心作用是为 OpenStack 中的虚拟机（VM）、容器等计算资源提供灵活、可扩展的网络连接能力，实现 “软件定义网络（SDN）” 的理念，摆脱传统硬件网络的限制。

一、Neutron 的核心定位：解决 “网络虚拟化” 问题

在传统物理机环境中，网络依赖交换机、路由器等硬件设备手动配置；而在 OpenStack 云环境中，虚拟机（由 Nova 组件管理）数量动态变化，需要网络能自动创建、配置和销毁—— 这正是 Neutron 的核心价值：

通过软件模拟物理网络设备（如交换机、路由器、防火墙），为每个租户（Tenant）提供独立的 “虚拟网络环境”，同时支持多种网络拓扑和技术选型，满足不同场景需求（如公有云、私有云、混合云）。

二、Neutron 的核心概念（基础组件）

Neutron 通过一系列抽象概念构建虚拟网络，这些概念对应物理网络中的设备 / 逻辑，但由软件实现：

概念（Concept） 物理网络对应 核心作用
Network（网络） 物理交换机的 VLAN（广播域） 一个隔离的 “广播域”，类似物理网络中同一交换机下的网段，虚拟机的网卡（Port）必须连接到某个 Network
Subnet（子网） 物理网段（如 192.168.1.0/24） 为 Network 分配的 IP 地址段（支持 IPv4/IPv6），定义 IP 地址范围、子网掩码、网关、DNS 等网络参数
Port（端口） 交换机的物理端口 虚拟交换机上的 “端口”，用于连接虚拟机的网卡（vNIC）与 Network；每个 Port 会分配一个 Subnet 中的 IP 地址（自动 / 手动）
Router（路由器） 物理路由器 连接不同 Network（广播域）的虚拟设备，实现跨子网通信；支持静态路由、动态路由（如 BGP），并可关联 “外部网络” 实现云内资源访问公网
External Network（外部网络） 公网 / 数据中心核心网络 与 OpenStack 集群外物理网络打通的 “桥梁”（通常是公网或数据中心内部骨干网），虚拟机需通过 Router 关联 External Network 才能访问外部
Internal Network（内部网络） 数据中心内网（私有网段） 仅在 OpenStack 租户内部可见的网络，无法直接访问外部，需通过 Router 转发，安全性更高
三、Neutron 的核心功能：不止 “连接”，更重 “灵活与安全”

Neutron 不仅实现基础的网络连接，还提供丰富的高级功能，满足企业级需求：

  1. 网络隔离：租户间 / 租户内资源隔离

  2. 租户隔离：不同租户的 Network、Subnet、Router 完全独立，即使 IP 地址重叠也不会冲突（由 Neutron 的租户 ID（Tenant ID）机制实现）。

  3. 内部隔离：同一租户内可创建多个 Network，默认不互通（需通过 Router 连接），避免广播风暴和安全风险。

  4. 地址管理：自动分配与静态配置

  5. DHCP 服务：Neutron 默认提供 DHCP 功能（由neutron-dhcp-agent组件实现），为 Port 自动分配 Subnet 中的 IP 地址、DNS、网关等参数，无需手动配置。

  6. 静态 IP：支持为 Port 手动指定固定 IP（如数据库服务器需要固定地址），避免 DHCP 租期到期后 IP 变化。

  7. 跨子网通信：路由转发

  8. 当虚拟机需要访问其他 Subnet 的资源时，需通过 Neutron Router 实现路由转发：Router 会为每个关联的 Subnet 分配一个 “网关 IP”（如 Subnet 192.168.1.0/24 的网关为 192.168.1.1），虚拟机将流量发送到网关，由 Router 转发到目标 Subnet。

  9. 公网访问：NAT 与浮动 IP（Floating IP）

  10. 云内虚拟机的 IP（如 192.168.1.100）是 “私有 IP”，无法直接被公网访问。Neutron 通过

浮动 IP（Floating IP）

解决此问题：

  • 浮动 IP 是从 “External Network” 中分配的公网 IP（如 203.0.113.10）。

  • 将浮动 IP 绑定到虚拟机的 Port 上，Neutron 通过 NAT（网络地址转换）实现 “私有 IP ↔ 浮动 IP” 的映射，公网可通过浮动 IP 访问虚拟机，虚拟机也可通过浮动 IP 访问公网。

  • 安全防护：安全组（Security Group）

  • 安全组

是 Neutron 的核心安全组件，类似 “虚拟防火墙”，用于控制虚拟机的入站（Ingress）和出站（Egress）流量：

  • 每个 Port 默认关联一个 “默认安全组”，默认规则为 “允许所有出站流量，拒绝所有入站流量”。

  • 用户可自定义安全组规则（如允许 SSH（22 端口）、HTTP（80 端口）入站流量），并将安全组关联到多个 Port，实现批量防护。

  • 高级网络功能

  • 负载均衡（Load Balancing）：通过Octavia项目（Neutron 的官方负载均衡插件）实现，为多台虚拟机提供流量分发（如 HTTP 负载均衡），提升服务可用性。

  • VPN 服务：通过VPNaaS（VPN as a Service）插件，实现 OpenStack 云环境与企业本地数据中心的加密通信（如 IPsec VPN）。
  • 防火墙即服务（FWaaS）：通过FWaaS插件，提供租户级别的虚拟防火墙，控制跨 Router 的流量（比安全组粒度更粗，适合租户边界防护）。
四、Neutron 的架构：模块化与插件化

Neutron 采用模块化架构，核心组件与具体网络技术解耦，支持通过 “插件（Plugin）” 和 “代理（Agent）” 扩展功能，适配不同的网络场景（如物理交换机集成、SDN 控制器对接）。

  1. 核心组件

  2. Neutron Server：API 服务端，接收用户 / 其他 OpenStack 组件（如 Nova）的网络请求（如创建 Network、绑定 Port），并调用插件处理。

  3. Plugin（插件）

：实现网络逻辑的核心模块，负责将 API 请求转换为具体的网络操作。常见插件包括：

  • ML2（Modular Layer 2）：Neutron 默认的二层插件，支持多种 “机制驱动（Mechanism Driver）”，如 Linux Bridge、Open vSwitch（OVS）。

  • OVS Plugin：基于 Open vSwitch（开源虚拟交换机）的插件，支持复杂的二层网络功能（如 VxLAN、GRE 隧道）。

  • Agent（代理）

：运行在计算节点（Compute Node）或网络节点（Network Node）上的服务，执行具体的网络配置（如创建虚拟端口、配置 DHCP）：

  • neutron-linuxbridge-agent/neutron-ovs-agent：在计算节点上配置虚拟交换机，连接虚拟机网卡。
  • neutron-dhcp-agent：提供 DHCP 服务。

  • neutron-l3-agent：实现 Router 的路由转发和 NAT 功能。

  • 常见部署模式：网络节点 vs 分布式路由

  • 传统网络节点模式：所有 Router、DHCP 服务集中在 “网络节点” 上，计算节点仅负责虚拟机的二层网络连接。优点是部署简单，缺点是网络节点可能成为性能瓶颈。

  • 分布式路由（DVR）模式：Router 的 “转发功能” 分布到每个计算节点上，仅 “网关功能” 保留在网络节点。优点是避免单点瓶颈，提升跨子网通信性能，适合大规模部署。
五、Neutron 与其他 OpenStack 组件的协作

Neutron 并非独立工作，需与其他核心组件配合，完成云资源的网络配置：

  1. 与 Nova（计算服务）协作：当 Nova 创建虚拟机时，会向 Neutron 请求 “创建 Port 并绑定到指定 Network”，Neutron 分配 IP 后返回给 Nova，Nova 将 IP 配置到虚拟机的网卡上。
  2. 与 Glance（镜像服务）协作：无直接协作，但虚拟机的操作系统镜像（如 Linux）需支持 Neutron 的虚拟网卡驱动（如 virtio-net）。
  3. 与 Cinder（块存储服务）协作：无直接协作，但块存储设备（如虚拟机的硬盘）的访问不经过 Neutron，仅虚拟机的网络流量通过 Neutron。
  4. 与 Keystone（身份认证服务）协作：Keystone 为 Neutron 提供身份认证和权限控制，确保只有授权用户（如租户管理员）才能操作网络资源。
六、总结

OpenStack Neutron（网络服务）是云环境的 “网络大脑”，其核心价值在于：

  • 以软件定义的方式，替代传统硬件网络，实现网络资源的自动化、弹性管理；
  • 为租户提供隔离、安全、灵活的虚拟网络环境，满足从简单 Web 服务到复杂企业级应用的网络需求；
  • 支持模块化扩展，可对接不同的 SDN 技术（如 OpenDaylight、Contrail），适应不同规模和场景的部署。
