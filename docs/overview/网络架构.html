httpd服务引擎

--with-mpm=MPM 是 Apache HTTP 服务器在源码编译时的一个核心配置选项，用于指定默认使用的 MPM（Multi-Processing Module，多处理模块）—— 即 Apache 处理并发请求的进程 / 线程模型。

核心作用：

MPM 决定了 Apache 如何管理进程和线程来响应客户端请求，直接影响服务器的并发处理能力、资源占用和稳定性。通过 --with-mpm=XXX 可以指定默认启用的 MPM 类型，可选值包括：

MPM 类型 适用场景与特点
prefork 传统的进程模型，为每个请求创建一个独立进程（无线程），稳定性高（一个进程崩溃不影响其他），但内存占用大，并发能力有限。适合需要兼容线程不安全模块（如旧版 mod_php）的场景。
worker 混合进程 + 线程模型，先创建多个进程，每个进程包含多个线程，每个线程处理一个请求。内存占用低于 prefork，并发能力更强，但线程安全要求高。
event 基于 worker 模型的改进版，引入 “事件驱动” 机制，能更高效地处理长连接（如 Keep-Alive），减少线程阻塞，并发性能最优，是现代 Apache 的推荐选择。
winnt 专为 Windows 系统优化的单进程多线程模型，利用 Windows 系统的线程特性，是 Windows 环境下的默认选项。

关键说明：

  1. 静态链接特性：默认情况下，通过 --with-mpm=MPM 指定的 MPM 会被 静态编译 到 Apache 中，成为唯一可用的进程模型（其他 MPM 无法动态切换）。
  2. 动态切换支持：若需要在运行时切换 MPM，需同时添加 --enable-mpms-shared 选项，此时指定的 MPM 会作为默认值，但其他 MPM 会被编译为动态模块，可通过配置文件切换。
  3. 选择建议：
  4. Linux/Unix 环境优先选择 event（性能最优）；
  5. 需兼容旧模块（如非线程安全的 PHP 扩展）时用 prefork；
  6. Windows 环境默认使用 winnt 即可
./configure --with-mpm=event ...  # 其他配置选项
